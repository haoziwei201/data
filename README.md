# 基于 MongoDB 的在线问卷系统（两阶段演进）

类似"问卷星"的简化在线问卷系统：注册用户创建问卷，通过 `/survey/<slug>` 短链分发，
他人登录或按问卷配置匿名填写，系统对回收的答卷自动统计。

本项目按课程要求分两阶段完成，第二阶段在**不推翻第一阶段**的前提下演进：

- **第一阶段**：账号、问卷生命周期（草稿→收集中⇄暂停→关闭）、三种题型与校验、
  数据化跳转规则、逐题导航填写、按卷统计，外加三项自主演进（暂停收集改题、
  题目模板导入、问卷级联删除）；
- **第二阶段（题目资产化）**：题目从"问卷私有内容"升级为独立资产——问卷里的题
  可显式「存入题库」复用、共享给其他用户、内嵌版本链（可追溯/可恢复/多版本共存，
  加入问卷与卷内切换都可选任意版本）、已发布问卷改题走 copy-on-write 分叉
  （旧答卷口径永不失真）、使用情况反查、单题跨问卷统计。
  存量数据经幂等迁移脚本升级，`responses` 集合一行未动。

两阶段全部 114 个自动化用例通过（第一阶段 71 个用例**未修改一行**）、
58 步端到端冒烟通过——"没有推倒重做"的直接证据。

## 1. 技术栈与依赖

| 组件 | 选型 | 说明 |
|---|---|---|
| 数据库 | MongoDB 4.x / 8.x（本机开发使用 8.3） | 全部数据存 MongoDB，未使用任何关系库 |
| 后端 | Python 3.11 + Flask 3.1 + pymongo 4.18 | 六组 API 蓝图 + 题型注册表 + 跳转引擎 |
| 前端 | 原生 HTML/JS（8 个页面 + 1 CSS + 2 公共 JS） | 无构建步骤、无前端框架 |
| 测试 | pytest（单元 + API 集成 + 前端静态检查）+ 自研冒烟脚本 | 详见第 6 节 |
| 报告 | ReportLab（`generate_report.py`） | 报告生成脚本（第二阶段版待生成时更新） |

安装依赖：

```
pip install -r requirements.txt      # flask / pymongo / pytest
```

## 2. 快速开始

1. 安装并启动 MongoDB（Windows 安装后一般为名为 `MongoDB` 的系统服务，默认端口 27017）；
2. 安装依赖（见上）；
3. 启动服务：

   ```
   cd survey-system
   python run.py
   ```

4. 浏览器打开 <http://127.0.0.1:5000>，注册账号即可使用。

30 秒建一份测试问卷：注册 → 创建问卷（可勾选允许匿名）→ 编辑页点「导入题目模板 →
内置测试模板」→「发布问卷」→ 复制 `/survey/xxxxxx` 链接分发填写 → 点「统计」。

第二阶段推荐体验路径：「我的问卷」页下方即内嵌**我的题库**——创建一道备选题
（选项与问卷编辑器同款的逐行输入）→ 在任意问卷编辑页「从题库选题」加入 →
题目详情页看**版本历史**（编辑/恢复）与**被哪些问卷使用** → 收几份答卷后点
**跨问卷统计**看这道题在所有问卷中的总体分布。

## 3. 配置说明

配置集中在 `app/config.py`，全部支持环境变量覆盖，**不需要修改任何代码**：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `MONGO_URI` | `mongodb://localhost:27017` | MongoDB 连接串。数据库不在本机或改了端口时修改 |
| `DB_NAME` | `survey_db` | 业务数据库名。同一台 MongoDB 上隔离多套环境时各用各的库名 |
| `SECRET` | `dev-secret-change-me` | 登录令牌签名密钥。**部署/提交演示前务必改为随机长字符串**；改密钥会使所有已发令牌失效（用户需重新登录），密码本身不受影响 |
| `TOKEN_TTL` | `604800`（7 天） | 登录令牌有效期（秒） |
| `HOST` / `PORT` | `127.0.0.1` / `5000` | 监听地址与端口。局域网演示可 `HOST=0.0.0.0` |
| `DEBUG` | 空 | 设为 `1` 开启 Flask 调试模式（代码热重载，仅开发用） |

示例（Git Bash，端口与密钥自定义）：

```bash
PORT=8000 SECRET=please-change-me python run.py
```

测试环境的配置隔离（一般无需改动）：`tests/conftest.py` 在导入应用前将
`DB_NAME` 固定为 `survey_test_db`，并支持 `TEST_MONGO_URI` 指向别的 MongoDB 实例，
因此**跑测试不会触碰业务库 `survey_db` 的数据**。

其他约定：所有时间按服务器本地时间处理；密码以 PBKDF2-SHA256（10 万轮、随机盐）
哈希存储，数据库中不存在明文。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 页面提示"数据库无法连接"（503） | MongoDB 未启动或 `MONGO_URI` 不对；Windows 服务名一般为 MongoDB，`net start MongoDB` 后重试 |
| 注册提示"用户名已存在"（409） | 用户名唯一，换一个即可 |
| 修改了 `SECRET` 后所有用户被登出 | 预期行为：旧令牌签名失效，重新登录即可，数据不受影响 |
| 发布时提示"跳转规则存在循环/目标不存在"（409） | 按提示修正对应题目的跳转规则 |
| 已发布问卷改题后，编辑页题目 id 变了 | **预期行为（第二阶段核心机制）**：有答卷的问卷改题走 copy-on-write 分叉，旧实例退役保留，历史答卷与统计口径不变；同卷跳转目标自动改指新实例 |
| 题库里没有我问卷里建的题 | 预期行为：建题不自动入库；在问卷编辑页对该题点「存入题库」即可（题目行会从"未入库"变为"题库 vN/M"） |
| 从题库选题提示"该题目已在问卷中"（409） | 同一问卷对同一道题只允许一个活跃实例（统计按身份归并的前提）；如需再用可先删卷内该题 |
| 共享来的题目不能编辑/存回题库（403） | 题库写操作仅所有者；共享使用者可在自己卷内修改快照或等所有者更新后「升级」 |
| 端口被占用 | `PORT=5001 python run.py`；若 5000 上有残留旧服务进程（数据"对不上"），`netstat -ano \| findstr :5000` 查 PID 后 taskkill |

## 8. 关键设计决策速览

第一阶段：

1. **4 个集合**：users / surveys / questions / responses——题目、答卷不嵌入问卷文档（无界数组、并发热点）。
2. **题型 = 判别联合**：公共字段 + `type` + `config` 子文档，新增题型只需注册新策略类，数据库零改动。
3. **校验与跳转全部数据化**：`config` 存校验参数，`jumpRules` 存统一条件模型，代码只解释执行。
4. **选项只存稳定 key**：改文案不影响历史答卷与统计；key 永不复用。
5. **两级删除口径**：问卷删除 = 聚合根级联硬删除；单题删除 = 软删除保历史。
6. **收集中冻结、暂停后解冻**：恢复收集前重校验跳转图。

第二阶段（题目资产化，详见 `docs/数据库设计.md` 第二阶段章节）：

7. **题目 = 身份 + 版本 + 实例三层**：`question_bank` 存身份与内嵌版本链；
   `questions` 保持"问卷内实例"形态并持内容快照（血统字段 rootId/bankVersion/basedOn）。
8. **实例快照模型而非引用集合**：第一阶段全部对外语义（题目 id 即答卷存储键）原样保留，
   71 个旧测试零改动通过；题库身份删除不波及问卷。
9. **改题即分叉（copy-on-write）**：发布过或有答卷的问卷改题生成新实例接管题位，
   旧实例软删、内容永不篡改——需求"改题不得影响已发布问卷"的直接落地。
10. **统计按身份归并**：分叉/删除/重加的同一道题在卷内合并为一行（行 id 为锚点实例；
    未入库题目沿 basedOn 血统链归并）；跨问卷统计复用同一套聚合管道按 rootId 汇总。
11. **题库显式入库**（第二阶段中期调整）：问卷建题默认卷内私有，用户「存入题库」
    才创建身份——题库只含精选资产，不被草稿过程题淹没。
12. **迁移幂等、旧数据零迁移**：`responses` 一行不动；`schemaVersion` 标记 + 缺省值兼容读取，
    兑现第一阶段设计文档第八节的演进预案。
