# 基于 MongoDB 的在线问卷系统

类似"问卷星"的简化在线问卷系统：注册用户创建问卷，通过 `/survey/<slug>` 短链分发，
他人登录或按问卷配置匿名填写，系统对回收的答卷自动统计。数据库课程大作业第一阶段成果，
在初始需求之上包含三项自主演进（暂停收集改题、题目模板导入、问卷级联删除）。

## 1. 技术栈与依赖

| 组件 | 选型 | 说明 |
|---|---|---|
| 数据库 | MongoDB 4.x / 8.x（本机开发使用 8.3） | 全部数据存 MongoDB，未使用任何关系库 |
| 后端 | Python 3.11 + Flask 3.1 + pymongo 4.18 | 语言与框架为作业允许范围内的自由选型 |
| 前端 | 原生 HTML/JS（5 个页面 + 1 个 CSS + 1 个公共 JS） | 无构建步骤、无前端框架 |
| 测试 | pytest（单元 + API 集成）+ 自研冒烟脚本 | 详见第 6 节 |
| 报告 | ReportLab（`generate_report.py`） | 生成《项目完成报告（第一阶段）》PDF |

安装依赖：

```
pip install -r requirements.txt      # flask / pymongo / pytest
```

## 2. 快速开始

1. 安装并启动 MongoDB（Windows 安装后一般为名为 `MongoDB` 的系统服务，默认端口 27017）；
2. 安装依赖（见上）；
3. 启动服务：

   ```
   cd survey-system
   python run.py
   ```

4. 浏览器打开 <http://127.0.0.1:5000>，注册账号即可使用。

30 秒建一份测试问卷：注册 → 创建问卷（可勾选允许匿名）→ 编辑页点「导入题目模板 →
内置测试模板」→「发布问卷」→ 复制 `/survey/xxxxxx` 链接分发填写 → 编辑页/列表页点「统计」。

## 3. 配置说明

配置集中在 `app/config.py`，全部支持环境变量覆盖，**不需要修改任何代码**：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `MONGO_URI` | `mongodb://localhost:27017` | MongoDB 连接串。数据库不在本机或改了端口时修改，如 `mongodb://192.168.1.10:27017` |
| `DB_NAME` | `survey_db` | 业务数据库名。同一台 MongoDB 上隔离多套环境（如开发/演示）时各用各的库名 |
| `SECRET` | `dev-secret-change-me` | 登录令牌签名密钥。**部署/提交演示前务必改为随机长字符串**；改密钥会使所有已发令牌失效（用户需重新登录），密码本身不受影响 |
| `TOKEN_TTL` | `604800`（7 天） | 登录令牌有效期（秒） |
| `HOST` / `PORT` | `127.0.0.1` / `5000` | 监听地址与端口。局域网演示可 `HOST=0.0.0.0` |
| `DEBUG` | 空 | 设为 `1` 开启 Flask 调试模式（代码热重载，仅开发用） |

示例（Git Bash，端口与密钥自定义）：

```bash
PORT=8000 SECRET=please-change-me python run.py
```

测试环境的配置隔离（一般无需改动）：`tests/conftest.py` 在导入应用前将
`DB_NAME` 固定为 `survey_test_db`，并支持 `TEST_MONGO_URI` 指向别的 MongoDB 实例，
因此**跑测试不会触碰业务库 `survey_db` 的数据**。

其他约定：所有时间（截止时间、提交时间）按服务器本地时间处理；密码以 PBKDF2-SHA256
（10 万轮、随机盐）哈希存储，数据库中不存在明文。

## 6. 测试方法与预期结果

### 6.1 自动化测试（pytest，71 项）

```
cd survey-system
python -m pytest -q
```

预期结果（连本机 MongoDB 时）：

```
...................................................................      [100%]
71 passed in 3~6s
```

- 三层构成：`test_question_types.py` 20 项（四题型校验边界值）、`test_jump.py` 11 项
  （条件命中语义与规则顺序）、`test_api_flow.py` 40 项（注册登录、问卷生命周期与
  状态机、权限隔离、跳转填写、统计正确性、模板导入、级联删除）；
- 数据隔离：自动使用独立测试库 `survey_test_db`，每个用例前后清空集合，
  **可随时反复运行，不影响业务数据**；
- MongoDB 未启动时：单元测试（31 项）照常通过，集成测试自动 skip 并提示
  "MongoDB 不可用"，不会误报失败。

### 6.2 端到端冒烟（28 步）

先启动服务（`python run.py`），另开终端：

```
python scripts/smoke_test.py
```

预期结果：每步打印 `[PASS]`，末尾输出

```
全部冒烟测试通过 ✅
```

流程覆盖：注册 A/B → 建卷（开匿名）→ 加 4 题（第 1 题选"否"跳第 3 题）→ 发布 →
逐题导航验证跳转 → 非法答案 400 → 登录提交 + 匿名提交 ×2 → 暂停收集（填写 403）→
暂停期加题 → 继续收集（填写恢复）→ 新问卷导入内置模板 → 导入后直接发布 →
验证导入问卷的跳转生效 → 查看统计 → 级联删除问卷（填写链接变 404）。

统计环节的典型预期输出（数值随该轮提交而变）：

```
总答卷数: 3
第1题 你是否年满18岁: 是=1, 否=2 (回答3人)
第2题 你的年龄: 平均=20 最小=20 最大=20
第3题 你喜欢的水果: 苹果=1, 香蕉=1, 西瓜=1, 葡萄=1 (回答3人)
```

任一步骤 `[FAIL]` 即为回归：脚本会打印实际状态码与期望值及服务端返回体，
先按提示定位（区分服务端缺陷还是脚本问题），修复后重跑。

### 6.3 手工测试（网页路径，14 项）

按 `docs/测试用例.md` 的 H1–H14 执行，覆盖自动化测不到的页面行为，重点三条：

- H2/H3：编辑页「导入题目模板」一键生成 4 题后，当前页直接「发布问卷」；
- H8：编辑页「暂停收集」改一道题后「继续收集」，暂停期间填写链接应提示已暂停；
- H12/H13：未登录用户打开"需登录"问卷链接 → 注册/登录 → **自动回到该问卷填写页**。

### 6.4 快速健康检查

```
curl http://127.0.0.1:5000/api/health
```

预期：`{"db":true,"status":"ok"}`。`db:false`（HTTP 503）表示服务在跑但连不上
MongoDB，先检查 MongoDB 服务是否启动、`MONGO_URI` 是否正确。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 页面提示"数据库无法连接，请确认 MongoDB 已启动"（HTTP 503） | MongoDB 服务未启动或 `MONGO_URI` 不对；Windows 服务名一般为 MongoDB，`net start MongoDB` 后重试 |
| 注册提示"用户名已存在"（409） | 用户名唯一，换一个即可 |
| 修改了 `SECRET` 后所有用户被登出 | 预期行为：旧令牌签名失效，重新登录即可，数据不受影响 |
| 发布时提示"跳转规则存在循环/目标不存在"（409） | 按提示修正对应题目的跳转规则（环指 A 跳 B、B 又跳回 A 之类的配置） |
| 端口被占用 | `PORT=5001 python run.py` 换端口启动 |

## 8. 关键设计决策速览

1. **4 个集合**：users / surveys / questions / responses——题目、答卷不嵌入问卷文档（无界数组、并发热点）。
2. **题型 = 判别联合**：公共字段 + `type` + `config` 子文档，新增题型只需注册新策略类，数据库零改动。
3. **校验与跳转全部数据化**：`config` 存校验参数，`jumpRules` 存统一条件模型，代码只解释执行。
4. **选项只存稳定 key**：改文案不影响历史答卷与统计；key 永不复用。
5. **两级删除口径**：问卷删除 = 聚合根级联硬删除；单题删除 = 软删除保历史——为第二阶段"旧数据必须保留"打底。
6. **收集中冻结、暂停后解冻**：统计口径稳定与发布后可修改的折中；恢复收集前重校验跳转图。
