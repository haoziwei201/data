# 系统说明

## 1. 系统架构

```
浏览器（原生 HTML/JS，8 个页面）
        │  fetch JSON（Bearer Token 认证）
        ▼
Flask 应用（run.py 启动）
 ├─ routes/auth.py      注册 / 登录 / 当前用户
 ├─ routes/surveys.py   问卷 CRUD、发布/关闭、跳转图校验
 ├─ routes/questions.py 题目 CRUD、排序（软删除）、题库选题/升级/存回（第二阶段）
 ├─ routes/fill.py      打开问卷、逐题导航、提交（路径回放）
 ├─ routes/stats.py     聚合统计（按题目身份归并，第二阶段）
 └─ routes/bank.py      题库：身份/版本链/共享/使用反查/跨问卷统计（第二阶段）
        │  pymongo
        ▼
MongoDB（users / surveys / questions / responses / question_bank 五个集合）
```

页面：index（登录/注册）、my（我的问卷 + **我的题库**卡片：备选题列表与创建）、
edit（编辑问卷）、fill（填写）、stats（整卷统计）+ 第二阶段新增 bank（完整题库，
含"共享给我的"）、question（题目详情：版本/使用/共享）、qstats（单题跨问卷统计）。
题库入口有两处：常用操作直达"我的问卷"页内嵌的"我的题库"卡片，
完整功能（共享列表/版本历史/跨卷统计）在独立题库页；两页共用同一份
建题表单组件 `web/bank-form.js`，避免逻辑双写。

横切支撑模块：

- `question_types.py`：**题型注册表**（策略模式）。每种题型实现
  `normalize(payload)`（规范化配置）、`check_answer(q, v)`（校验答案）、
  `normalize_value(q, v)`（入库规范化）三个静态方法。
- `jump.py`：**跳转引擎**。`next_destination(question, value)` 解释题目的
  `jumpRules` 数据，返回下一跳（题目 id / "end" / None=顺序下一题）。
- `security.py`：PBKDF2 密码哈希、HMAC 签名令牌（无状态，不占用集合）、
  `login_required` 装饰器。

## 2. 关键业务流程

### 2.1 填写导航（服务端驱动，逻辑不落前端）

填写页每次"下一题"调用 `POST /api/fill/<slug>/step`，携带到目前为止的全部答案。
服务端做三件事：

1. 校验所有已提交答案（查题型注册表）；
2. **回放路径**：从第 1 题出发，已答的题按其答案解释 `jumpRules` 决定下一跳，
   直到遇到第一道未答的题——它就是下一道应展示的题；
3. 返回该题（不含 `jumpRules`，导航逻辑不下发到前端）。

前端只维护"已见题目缓存 + 上一题栈"，不做任何跳转判断，
保证跳转语义在前后端只有一份实现。

### 2.2 提交与必答判定

`POST /api/fill/<slug>/submit` 同样回放路径，但走完整条路：

- 路径上未作答且 `required=true` 的题 → 400 报"必答"；
- 被跳转跳过的必选题**不**报错（测试 `test_submit_with_jump_skip` 验证）；
- 只有路径上的答案会被入库，路径外/非法题目的答案被拒绝或忽略。

入库时答案按题型规范化（文本去首尾空白、整数题 int 化），
`questionId` 存 ObjectId，多选存 key 数组，单选存 key 字符串。

### 2.3 发布前校验（跳转图检查）

发布时对全部未删除题目构建有向图（每题的默认下一题 + 全部规则目标）：

- 某规则的 `goto` 指向不存在的题目 → 409 拒绝发布；
- 图中存在环 → 409 拒绝发布（防止填写端死循环）。

### 2.4 统计

聚合管道（3 条）出裸数字：

- 管道 A：`$match → $unwind answers → $unwind answers.value → $group(qid+value)`
  —— 每个取值被选次数（多选数组被自然展开，标量原样通过）；
- 管道 B：`$group(qid) → $push value` —— 每题全部填写内容；
- 管道 C：`$group(qid) → $sum 1` —— 每题回答人数。

应用层把题目定义（含选项文本）与聚合结果合并成带标签报表：
选择题出"选项-票数-占比"，文本题列出全部内容，数字题计算平均/最小/最大。
支持 `?questionId=` 只看单题。

### 2.5 题目资产化流程（第二阶段核心）

题目 = 身份（question_bank 文档，含内嵌版本链）+ 问卷内实例（questions 文档，
持有内容快照）。关键流程：

- **建题不自动入库**（第二阶段口径调整）：问卷内新建/导入的题目默认未入库
  （rootId 为空），编辑页显示"未入库"标记；用户点「存入题库」后才创建身份
  （实例内容即 v1）成为可复用资产——题库只包含用户显式放入的题目；
- **选题入卷**：编辑页「从题库选题」可在题目身份的**任意版本**（v1~vN）中
  选择加入本卷（同身份同卷至多一个活跃实例）；
- **改题即分叉**（copy-on-write）：草稿无答卷 → 原地改；已发布过或有答卷 →
  生成新实例接管题位，旧实例软删退役、同卷跳转目标自动改指新实例，
  历史答卷仍指向旧实例（内容永不被篡改）；
- **版本链**：题库编辑（全部字段可改）/恢复/存回题库都是"追加新版本"，
  历史只增不改；卷内题目可随时「切换版本」到任意历史版本
  （草稿原地更新、冻结走分叉）；
- **跨卷统计**：单题统计按身份聚合所有问卷所有实例的答卷，含分卷明细。

## 3. 认证模型

- 注册：用户名唯一（唯一索引兜底），密码 PBKDF2-SHA256（10 万轮）加盐哈希。
- 登录：验证后签发 `body.signature` 形式的 HMAC 令牌（含 uid/username/exp），
  服务端无状态，无需 session 集合。
- 前端把令牌存 `localStorage`，每次请求带 `Authorization: Bearer <token>`。

## 4. 需求解释说明（两处需要说明口径的地方）

1. **"填写的人需要先登录" vs "支持匿名填写"**：实现为按问卷配置区分——
   `allowAnonymous=false`（默认）时必须登录才能填写；
   `allowAnonymous=true` 时允许未登录用户填写，答卷记录 `anonymous=true`、
   `userId=null`（创建者在统计中看不到填写者身份）。
2. **"同一个人填写多次（如果允许）"**：`allowMultipleSubmissions=false`（默认）时，
   登录用户重复提交返回 409；匿名答卷无法识别身份，不受该限制（如需严格限制
   可结合 IP 元数据，第一阶段未实现）。

## 5. 有意为之的约束

- **收集中冻结题目，暂停后解冻**：问卷状态机为
  `draft → published ⇄ paused → closed（终态）`。收集中（published）不允许改题，
  保证统计口径稳定；编辑者可随时"暂停收集"进入可编辑状态，改完"继续收集"
  重新开放——恢复时会重新做发布级校验（至少一题、跳转图无环、目标存在），
  因此暂停期的修改不会让填写端进入坏状态。
- **暂停期改题走分叉而非原地改（第二阶段修正）**：第一阶段暂停后原地修改
  题目内容，正是用户反馈"改了题、以前的问卷跟着变"的根源。第二阶段起，
  只要问卷发布过（即使暂停中）或已有答卷，改题一律生成新实例接管题位：
  新填写者看到新内容，旧答卷仍指向旧实例，统计按题目身份归并。草稿问卷
  （从未发布且无答卷）仍可原地修改。
- **暂停期改题的数据完整性保障**：题目删除仍是软删除；选项删除后 key 不复用，
  历史答卷中指向已删选项的计数在统计中归入"（已删除的选项）"行，总数不失真。
- **同一题目身份在同一问卷内只能出现一次**（重复从题库加入返回 409）：
  这是卷内统计按身份归并的前提；删除后重新加入同一道题，历史回答会并入
  同一行统计（视为同一道题的延续）。未入库题目没有身份，其 copy-on-write
  分叉沿 basedOn 血统链归并到本卷最初的实例，统计同样合并不分家。
- **题库只含显式入库的题目**（第二阶段口径调整）：问卷里建的题默认是卷内
  私有内容，「存入题库」后才进入资产体系；问卷删除时已入库的身份保留在题库。
- **跳转目标必须是已存在的题目**（保存时校验格式，发布/继续收集时校验存在性）：
  因此编辑器中配置跳转时目标下拉只列出当前已有题目。使用习惯：按顺序建题，
  需要跳转的规则可先建目标题、再回头编辑来源题补规则；或直接用"导入题目模板"
  快速获得一套配好跳转的题目。跳转规则属于问卷编排，不随题目进入题库；
  copy-on-write 分叉与导入时跳转目标都会自动重映射到本卷实例。
- **题目模板导入**：`POST /api/surveys/<id>/questions/import` 支持导入内置测试
  模板（4 道题，覆盖全部题型与跳转）或复制本人另一份问卷的题目；题目追加到
  末尾，跳转目标自动重映射到新题目 id，悬空目标原样保留并在恢复收集时拦截。
  第二阶段：从本人问卷导入会复用题目身份（题库使用情况跨卷可见），
  重复身份自动跳过。
- **问卷删除是聚合根级联硬删除，单题删除是软删除**：两者口径不同但都服务于
  数据一致性——题目和答卷只被所属问卷引用，整卷下线（统计数据也不再需要）时
  一并删除不会留下悬空引用；而仍在收集/统计中的问卷删单题必须软删除以保历史。
  删除返回实际清除的题目数与答卷数，前端确认框中会显示。
  第二阶段：题目**身份**（题库资产）不随问卷删除——用户历史题目保留在题库
  中可继续复用，确需清理可在题库页移除。
- **共享是最小权限的名单制**：题目共享给指定用户后，对方可查看版本、选题入卷、
  查看使用与统计；改版本、再共享、存回题库仅所有者。共享使用者对入卷题目
  的修改只发生在自己卷内的快照上，不影响题库与其他问卷。
- **登录后回到来源问卷**：需要登录的问卷在填写页提示"去登录/注册"并携带
  `?next=<问卷地址>`；登录页读取该参数（存入 localStorage，登录/注册成功后
  跳转），已登录用户点击问卷短链则直接进入填写。

## 6. 第二阶段演进预案的兑现情况（与数据库设计文档第八节对应）

| 第一阶段预留的演进方式 | 第二阶段的实际兑现 |
|---|---|
| 数据重组：按 schemaVersion 写增量迁移脚本 | `scripts/migrate_v1_to_v2.py`，幂等可重跑 |
| 功能下线用标记位停用 | 题库身份用 `deleted` 软删，问卷实例不受影响 |
| 新统计口径：聚合管道加阶段 | 跨问卷统计 = 同一套管道 + 按身份归并，存储层无感 |
| 新需求"加字段"而不是"改结构" | questions 补 rootId/bankVersion/basedOn；旧文档缺字段时按 v1 语义解释 |

## 7. 已知限制（第二阶段范围外）

- 无分页：问卷/答卷/题库数量很大时列表与统计需加分页与缓存（设计已预留 `survey_stats` 缓存方案）；
- 无邮箱/手机验证、无找回密码；
- 已关闭（closed）为终态，不可重新开放；收集中修改题目必须先暂停；
- 跨问卷统计按题库当前版本的内容展示选项文本；各卷使用的旧版本若选项有增删，
  其回答归入"（已删除的选项）"行，不逐版本拆分展示。
