# 测试用例

自动化测试：`python -m pytest -q`（114 个用例，含单元、API 集成与前端静态检查，
连接本地 MongoDB，使用独立测试库 `survey_test_db`，每个用例前后自动清空）。
端到端冒烟：先 `python run.py`，再 `python scripts/smoke_test.py`（58 步，覆盖两阶段全部核心链路）。

## 〇、完整测试流程（环境准备 → 四层测试）

### 第 0 步：环境准备

```
1. 启动 MongoDB（本机默认 mongodb://localhost:27017）
   Windows 服务方式：net start MongoDB；或手动：mongod
2. 安装依赖（首次）：pip install -r requirements.txt
3. 验证连通：curl http://127.0.0.1:5000/api/health 之前先确认 mongo 可达
   python -c "from pymongo import MongoClient; MongoClient('mongodb://localhost:27017',serverSelectionTimeoutMS=3000).admin.command('ping'); print('ok')"
```

### 第 1 层：单元测试（纯函数，不依赖网络）

```
python -m pytest tests/test_question_types.py tests/test_jump.py -q
```
覆盖题型校验规则（A1~A20）与跳转条件匹配语义（B1~B13）。

### 第 2 层：API 集成测试（pytest + Flask 测试客户端 + 独立测试库）

```
python -m pytest -q          # 全量 111 个；或只跑某一层：
python -m pytest tests/test_api_flow.py -q    # 第一阶段业务流（C1~C50）
python -m pytest tests/test_bank.py -q        # 第二阶段题目资产化（D1~D35）
python -m pytest tests/test_frontend_sanity.py -q   # 前端静态防回归（E1~E8）
```
说明：MongoDB 未启动时集成用例自动跳过（不算失败）；测试库 `survey_test_db`
每个用例前后自动清空，不会污染开发数据。

### 第 3 层：端到端冒烟（对运行中的真实服务）

```
python run.py                        # 终端 1：启动服务（默认 127.0.0.1:5000）
python scripts/smoke_test.py         # 终端 2：58 步全链路冒烟
```
冒烟以两个新注册用户走完整业务流：
第一阶段部分——注册/登录、建卷、四题型建题、跳转配置、发布、逐题导航、
非法答案拦截、答卷提交（登录/匿名/重复）、暂停⇄继续状态机、模板导入、
统计核对、问卷级联删除；
第二阶段部分——题库直接建题、问卷建题自动入库（含已删问卷的身份保留）、
共享与权限拦截、从题库选题入卷（含同卷去重 409）、一题多卷、版本链
（编辑 v2 / 恢复 v3）、使用反查、冻结卷改题分叉（copy-on-write）、
统计按身份归并、跨问卷统计、从题库移除身份后问卷照常可用。
预期输出：末行「全部冒烟测试通过 ✅」，任一步 FAIL 立即断言退出。

### 第 4 层：手工用例（浏览器页面操作，H1~H26）

启动服务后按「三、手工测试」表格逐条执行，覆盖自动化难以触达的页面交互
（登录回跳、题库卡片、选项行编辑、版本恢复按钮、升级确认框等）。

### 附：v1 → v2 数据迁移验证（仅升级存量部署时）

```
python scripts/migrate_v1_to_v2.py --dry    # 先 dry-run 看统计
python scripts/migrate_v1_to_v2.py          # 执行；幂等可重跑
python -m pytest tests/test_bank.py::TestMigration -q   # 迁移逻辑回归
```

### 一键回归（提交前的最小闭环）

```
python -m pytest -q && (python run.py &) && sleep 2 && python scripts/smoke_test.py
```

### E. 前端静态资源防回归（tests/test_frontend_sanity.py，8 个用例）

背景：会话 9/10 修复的两类前端缺陷（页面内联脚本重复声明 common.js 全局、
组件注入 id 与页面静态 id 冲突）都不会让 HTTP 变非 200，接口测试无法发现。
本组用例拉取静态页面做静态检查锁住这两类回归。

| 编号 | 测试 | 检查内容 | 结果 |
|---|---|---|---|
| E1 | 全部页面与资源可达 | 8 个页面 + common.js/bank-form.js/style.css 均 200 且非空 | 通过 |
| E2 | 外链脚本存在 | 每个页面引用的 <script src> 均可 200 取到 | 通过 |
| E3 | 全局名不重复声明 | 各页内联脚本不声明 common.js 已有的全局名（TYPE_LABELS/api/esc 等） | 通过 |
| E4 | 静态 id 不重复 | 各页静态标记内无重复 id（JS 模板内按需渲染的除外） | 通过 |
