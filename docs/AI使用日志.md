**本轮实现决策（AI 自主补充的口径，需要用户知悉）：**

- "停止问卷修改内容"落地为双向的 暂停⇄继续 两个动作，而不是单向停止：
  只停不改或只改不能恢复都不满足"随时停止、修改内容"的完整语义；
- 收集中（未暂停）仍禁止改题——统计口径稳定优先；这是把需求 2 与第一阶段的
  数据完整性约束做折中后的口径；
- 暂停期删除选项 ≠ 删除历史：统计端补了"已删除选项"聚合行（C45 验证）；
- 导入模板采用"追加"而非"替换"，避免误删已有题目；跳转重映射失败（悬空目标）
  的规则原样保留，由继续收集时的校验兜底报错。

**本轮实现决策（AI 自主补充的口径，需要用户知悉）：**

## 二、AI 使用说明（总结）

### AI 帮了什么

- 解析作业要求并结构化，避免遗漏评分点；
- 一次性生成整个系统的骨架代码：后端全部路由、题型注册表、跳转引擎、
  前端 5 个页面、测试与文档，人工工作量从数天缩短到主要是评审；
- 自动搭建并运行测试环境（安装 pytest、连接本地 MongoDB 跑通测试与冒烟）；
- 需求变更时在既有代码上增量演进（会话 4：状态机扩展 + 模板导入），
  未推翻已有结构——与作业"不得推倒重做"的要求一致。

### AI 做错了什么 / 局限在哪

- 生成的代码有 3 处真实缺陷（见上表）：状态码遗漏、BSON 类型不一致、
  脚本取键错误。前两处单看代码很难发现，完全靠测试暴露；
- 初版题型接口设计（normalize_value 不带题目上下文）考虑不周，实现中途才发现；
- 对"匿名填写 vs 填写需先登录"这一需求内在矛盾没有标准答案，只能给出
  一种自洽解释（allowAnonymous 开关），需要人确认口径是否符合课程预期。

### 自己改了什么 / 设计了什么

- 发现并修复上述 3 处缺陷，补齐 409 语义与 ObjectId 类型一致性；
- 决定跳转目标存题目 id 而非序号、发布后冻结题目集、服务端驱动导航等
  关键实现口径（部分源于设计文档，部分为实现期补充）；
- 设计并逐条编写了 56 个测试用例的断言（跳转路径回放、必答豁免、
  统计正确性等关键行为均由人工设计的用例验证）。

### 第二阶段补充（题目资产化改造）

**AI 帮了什么**

- 完成八条需求的差距分析与架构定位（识别出"同一根因：题目未资产化"）；
- 在既有代码上实现全部改造：题库蓝图、copy-on-write 编辑策略、按身份
  归并的统计、幂等迁移脚本、三个新页面与文档更新，第二阶段主实现一轮完成；
- 迁移设计保证旧数据零迁移（responses 一行不动），并用"第一阶段 71 个
  测试不改一行全部通过"自证没有推倒重做。

**AI 做错了什么**

- 主实现轮初稿 3 处低级错误（语法笔误 ×2、漏 import），靠测试暴露；
- import 重映射与去重跳过的组合逻辑初稿有索引错位，属"改一处忘另一处"；
- 两处口径漂移（perSurvey 结构、单题过滤的 total）是与第一阶段行为
  比对后才对齐的——AI 对"保持旧行为"的敏感度低于对新功能的敏感度。

**自己改了什么 / 设计了什么**

- 数据模型选型：在"引用集合模型"与"实例快照模型"之间拍板选后者
  （保住第一阶段全部对外语义与 71 个测试，答卷天然指向答题时内容）；
- 冻结判据从宽（发布过即冻结）、同卷同身份唯一、建题即入库、跳转不入
  题库、共享最小权限——五条业务口径均为人工确认的自主决策；
- 逐条设计 32 个第二阶段测试的断言（尤其分叉前后统计归并、迁移幂等、
  跨卷统计正确性），并人工核对修复了 AI 的两处口径漂移。
